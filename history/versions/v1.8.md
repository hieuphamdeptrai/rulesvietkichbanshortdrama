# v1.8 — PAYOFF & SATISFACTION ENGINE

**Frozen design history.** Runtime consolidation does not delete these rules.

**Current operational owner:** `modules/06-escalation-payoff.md`

## Frozen rules
- **H-18-001** — Pay off question, clue, promise, relationship, behavior, line, object, choice and arc according to setup weight.
- **H-18-002** — Payoff types: Information / Clue / Character / Relationship / Meaning.
- **H-18-003** — Setup weight should be proportional to payoff weight.
- **H-18-004** — Strong payoff uses Answer→Meaning→Consequence.
- **H-18-005** — Reward types include answer/twist/catharsis/theory confirmation/emotional release/reframe/justice/tragedy.
- **H-18-006** — Maintain micro / mid / arc / core payoff cadence.
- **H-18-007** — Use Payoff Cascade when one answer triggers several consequences without exposition dump.
- **H-18-008** — Callbacks should increase meaning, not merely repeat.
- **H-18-009** — Character payoff often arrives through choice.
- **H-18-010** — Relationship payoff often arrives through choice.
- **H-18-011** — Theory payoff ideally gives “I knew it” plus an additional unexpected layer.
- **H-18-012** — Allow catharsis/breathing room after major emotional payoff.
- **H-18-013** — Final twist should occur early enough in finale to leave consequence time; ~70–80% is guideline.
- **H-18-014** — Payoff pyramid can deepen danger→mystery→motive→character→relationship→meaning.
- **H-18-015** — Final Answer should cover WHO/WHAT/WHY/HOW/WHEN/WHY NOW/WHY PROTAGONIST as relevant.
- **H-18-016** — Use final-image symmetry when it adds meaning.
- **H-18-017** — Villain payoff includes motive/ideology/plan/downfall as appropriate.
- **H-18-018** — Theme is expressed through final action/choice, not lecture.
- **H-18-019** — Track Payoff Debt Ledger.
- **H-18-020** — Main story earns closure before season bait.
- **H-18-021** — Use roughly 80/20 closure as guideline, not rigid law.
- **H-18-022** — Ask whether answer makes journey better retrospectively.

# v4.2 — PROJECT INITIALIZATION, INTAKE & AUTO-ONBOARDING ENGINE

**Frozen design history.** Runtime consolidation does not delete these rules.

**Current operational owner:** `modules/15-onboarding-certification.md`

## Frozen rules
- **H-42-001** — Onboarding must turn incomplete ideas/scenes/characters/images/twists/endings/constraints into a structured project without forcing a long form.
- **H-42-002** — Intake is not an interview; determine what the user has, what is missing, and what actually blocks the next step.
- **H-42-003** — Ask only for missing information that prevents the next safe high-leverage action.
- **H-42-004** — Use provisional assumptions and defaults to reduce friction when they are safe; do not use them to decide high-leverage story truth.
- **H-42-005** — Classify input types: Raw Idea/Premise/Character-first/Twist-first/Scene-first/Genre-first/Image-first/Ending-first/Production-first/Existing Project.
- **H-42-006** — Classify project mode/state/confidence/missing blockers/next best action immediately.
- **H-42-007** — Intake confidence describes confidence in understanding user intent, not story quality.
- **H-42-008** — Parse WHO/SITUATION/DESIRE/STAKE/CURIOSITY/FORMAT as available without requiring all fields explicitly.
- **H-42-009** — Distinguish EXPLICIT, IMPLIED, and UNKNOWN facts.
- **H-42-010** — Never promote implied information to Locked Canon.
- **H-42-011** — Label temporary assumptions as PROVISIONAL with reason.
- **H-42-012** — Use a limited Assumption Budget; too many assumptions signal insufficient understanding.
- **H-42-013** — Do not silently assume Final Truth, villain identity, protagonist identity, ending, or core relationship outcome.
- **H-42-014** — Low-risk operational defaults may be provisional and easy to override.
- **H-42-015** — Keep defaults in a central profile; defaults are not canon.
- **H-42-016** — Explicit user choices override all defaults.
- **H-42-017** — Provide QUICK START / GUIDED / DEEP INTAKE / IMPORT modes and select them by task depth.
- **H-42-018** — Quick Start parses brief, creates minimal assumptions, forms a Project Seed, and moves into development without form-filling.
- **H-42-019** — Guided Mode presents 2–4 meaningful choices when ambiguity materially changes story.
- **H-42-020** — Deep Intake is reserved for professional/constraint-heavy projects and should still be staged.
- **H-42-021** — Import Mode reverse-engineers existing material instead of restarting premise design.
- **H-42-022** — Import workflow: read→extract canon candidates/characters/mysteries→detect contradictions→infer state→mark uncertainty→build skeleton→audit→recommend next action.
- **H-42-023** — Existing drafts are not auto-canonized; contradictory/placeholder/abandoned elements remain provisional until validated.
- **H-42-024** — The first useful response should make the project more concrete rather than explain SDCS theory.
- **H-42-025** — Introduce Project Seed with Working Title/Core Concept/Protagonist/Unusual Situation/Primary Curiosity/Personal Stake/Story Lock/Likely Genre/Format Assumption/Open Decisions.
- **H-42-026** — Project Seed stabilizes concept but is not a blueprint and should not prematurely define culprit/arcs/episode cliffs.
- **H-42-027** — After seed, route naturally to Premise Forge.
- **H-42-028** — An internal INPUT→SEED→IDEA→PREMISE progression may be used without burdening the user.
- **H-42-029** — Create a formal Project ID only when the user indicates ongoing development and a seed is concrete enough.
- **H-42-030** — Working title is provisional and never blocks development.
- **H-42-031** — When clarification is truly necessary, prioritize format, primary experience, hard constraints, and core user intent.
- **H-42-032** — Do not ask low-leverage visual/metadata questions early unless story-critical.
- **H-42-033** — Extract and preserve the original Creative Spark that attracted the user to the concept.
- **H-42-034** — Project may store priority such as Curiosity-first/Emotion-first/Romance-first/Production-first and use it to weight decisions.
- **H-42-035** — Infer explicit goals already stated by the user and do not ask them again.
- **H-42-036** — Extract constraints such as supernatural limits, period, cast/location limits, narration, violence, etc.
- **H-42-037** — Classify constraints as HARD/SOFT/ASPIRATIONAL; explicit user constraints outrank defaults.
- **H-42-038** — Detect contradictory constraints and surface tradeoffs or design-compatible reframing rather than silently violating one.
- **H-42-039** — Resolve many intent tensions through design rather than interrogation.
- **H-42-040** — Auto-reformulate raw ideas into clear premise candidates so the user can see how the system understood them.
- **H-42-041** — For ambiguous high-level briefs, briefly mirror understanding and proceed rather than create a confirmation loop.
- **H-42-042** — Read current conversation/project context before asking; never repeat known questions.
- **H-42-043** — Detect CREATE / RESUME / IMPORT / CLONE / EXPERIMENT modes.
- **H-42-044** — Clone mode reuses requested style/format defaults but not story canon, characters, twists, or props unless explicitly requested.
- **H-42-045** — Genre/project templates are starting profiles, not plot templates.
- **H-42-046** — Initialize only lean minimum project files and create other files lazily.
- **H-42-047** — Do not create dozens of empty ledgers at project start.
- **H-42-048** — Initial project state should clearly identify current state/mode/locked/provisional/open/next action.
- **H-42-049** — Generate a compact Bootstrap early for portable continuity.
- **H-42-050** — Early health uses light concept signals rather than false-precision scoring.
- **H-42-051** — Intake depth must match input depth: raw idea light, full script deep.
- **H-42-052** — If the user asks for a local one-off task, do not initialize a full project unnecessarily.
- **H-42-053** — Distinguish ONE-OFF mode from stateful PROJECT mode.
- **H-42-054** — Auto-onboarding flow: Receive→Classify Input→Detect Project Mode→Extract Facts/Constraints→Identify High-Risk Unknown→Apply Safe Defaults→Seed→Light Validate→Determine State→Activate Minimum Engine.
- **H-42-055** — Onboarding should feel like story development, not administration.
- **H-42-056** — Ask meaningful decisions while creating, offering distinct options and a recommendation where helpful.
- **H-42-057** — Classify questions BLOCKING/DEFERABLE/INFERABLE/IRRELEVANT NOW.
- **H-42-058** — Keep blocking questions to roughly 1–3 at a time.
- **H-42-059** — Store deferred development questions and let scheduler decide when they become due.
- **H-42-060** — Optimize information gain per user question: Creative Impact × Current Urgency ÷ User Effort.
- **H-42-061** — Choice options must be structurally distinct, not cosmetic.
- **H-42-062** — Default autonomy is collaborative; AI handles low-risk decisions while major creative locks are surfaced unless user grants broader autonomy.
- **H-42-063** — User behavior such as “cái nào hợp lý thì làm” authorizes proactive low/medium-risk decisions but not silent destructive canon changes.
- **H-42-064** — Project Priority Profile may include Bingeability/Originality/Emotional Impact/Production Ease/Prestige/Speed.
- **H-42-065** — Collect target audience sophistication only when it changes design; avoid unnecessary demographic bureaucracy.
- **H-42-066** — Collect content/platform/production contracts just in time.
- **H-42-067** — Story-first default keeps production-aware moderate assumptions unless production constraints are explicitly core to the premise.
- **H-42-068** — Image-first onboarding extracts visible design facts only; do not invent backstory/personality without need.
- **H-42-069** — Scene-first onboarding determines whether the scene is opening/midpoint/finale/inspiration before building premise around it.
- **H-42-070** — Twist-first onboarding must prove there is an interesting surface story and engine before/after the twist.
- **H-42-071** — Ending-first onboarding should work backward from emotional truth/final choice/core mystery/premise.
- **H-42-072** — Character-first onboarding places the character in a situation that attacks Want/Fear/False Belief rather than writing biography.
- **H-42-073** — Genre-first onboarding treats genre as promise and finds a specific contradiction/signature.
- **H-42-074** — Production-first onboarding treats constraints such as one room/two actors as creative engines.
- **H-42-075** — Import should identify what the user wants preserved and treat central premise/characters as prefer-preserve if unspecified.
- **H-42-076** — Legacy migration can be progressive: State+Canon→Characters+Episodes→Mystery/Clue/Payoff→Production model.
- **H-42-077** — Light intake validation checks protagonist candidate, situation, curiosity, reason to stay, and format plausibility.
- **H-42-078** — Weak raw concepts should route to Premise Forge rather than be prematurely rejected.
- **H-42-079** — A good intake increases clarity/specificity/curiosity/direction without overlocking.
- **H-42-080** — Onboarding hard fails include ignored explicit constraint, silently invented major canon, unnecessary giant form, premature blueprint, wrong project mode, provisional/locked confusion, or screenplay before concept.
- **H-42-081** — Use intake flags for ambiguity/constraint conflict/assumption overload/premature canon/blueprint/wrong mode/insufficient engine/user-intent drift.
- **H-42-082** — Creative Spark alignment should be checked at major locks to prevent development drifting from the user’s original attraction.
- **H-42-083** — Initial Decision Log stores only meaningful choices; initial Open Questions and Issues are scheduled, not dumped at user.
- **H-42-084** — Initial Project Plan should be minimal NOW/NEXT/LATER.
- **H-42-085** — If Next Best Action is obvious, auto-start it unless the user asked only for analysis; do not end with unnecessary “what next?”.
- **H-42-086** — Administration (IDs/state/schema/dependencies) should be mostly invisible to default users; expert mode may expose it.
- **H-42-087** — Use progressive disclosure and just-in-time questioning; stop intake when next action can be safely performed.
- **H-42-088** — Users never need to know SDCS module numbers or internal machinery to use the skill.
- **H-42-089** — Every key intake field may track provenance USER/IMPORTED/INFERRED/DEFAULT/PROPOSED/LOCKED_DECISION so the system does not misattribute choices.
- **H-42-090** — Project Seed, Creative Spark, Hard Constraints, and User Priorities are high-salience project memory.
- **H-42-091** — Operational profile may store autonomy/quality mode/production mode/language separately from story canon.
- **H-42-092** — Rapid Prototype mode is non-canon until promoted and then must pass missing gates.
- **H-42-093** — Onboarding routes broken imports to Rescue Mode, ambiguous interpretations to Branching, and style-first/emotion-first/curiosity-first/world-first/object-first/audio-first seeds to appropriate engines.
- **H-42-094** — Any fragment can be treated as a seed type rather than rejected as incomplete.
- **H-42-095** — Derive 2–5 audience questions from a seed and select a specific/personal/expandable/payoff-capable primary question.
- **H-42-096** — Extract Story Lock (“why can’t protagonist leave?”) and personal relevance early; use candidate mechanisms when needed.
- **H-42-097** — Run lightweight longevity and production prechecks before stretching a thin premise to a long episode count.
- **H-42-098** — Adapt constraints while preserving the original Creative Spark rather than killing the concept unnecessarily.
- **H-42-099** — Final onboarding principle: a reusable skill must know how to start correctly from incomplete natural-language intent, not require the user to know how to prompt it.

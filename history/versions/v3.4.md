# v3.4 — STORY SCHEMA & MACHINE-READABLE PROJECT MODEL

**Frozen design history.** Runtime consolidation does not delete these rules.

**Current operational owner:** `modules/12-schema-compiler.md`

## Frozen rules
- **H-34-001** — Use human Markdown + machine-readable YAML/JSON.
- **H-34-002** — Define source-of-truth and never duplicate without linkage.
- **H-34-003** — Structured facts/state are well suited to YAML; creative explanation to Markdown.
- **H-34-004** — Core entities: PROJECT / CHARACTER / RELATIONSHIP / MYSTERY / QUESTION / CLUE / PROP / LOCATION / EVENT / ARC / EPISODE / SCENE / SHOT / DECISION / ISSUE / MEMORY ITEM / CONTEXT PACK / PRODUCTION ASSET.
- **H-34-005** — Project is a graph, not merely folder tree.
- **H-34-006** — Use stable unique readable IDs.
- **H-34-007** — ID examples: PRJ-001 / CHA-LINH / REL-LINH-MINH / MYS-* / CLU-014 / OBJ-* / EP-012 / EP12-SC03 / EP12-SC03-SH04 / DEC-021.
- **H-34-008** — Statuses: DRAFT / PROVISIONAL / APPROVED / LOCKED / RETIRED / SUPERSEDED.
- **H-34-009** — Project schema includes id/title/version/sdcs_version/current_state/current_mode/genre/tone/duration/episode count/branch/status.
- **H-34-010** — Character schema includes role/public face/want/need/wound/false belief/fear/loyalties/secret refs/knowledge refs/strategy/moral boundary/breaking point/arc/visual/current state.
- **H-34-011** — Secret is separate entity.
- **H-34-012** — Secret stores holder/truth/hidden_from/reason_hidden/risk/behavioral_effect/reveal_plan/status.
- **H-34-013** — Relationship state is directional.
- **H-34-014** — A→B need not equal B→A.
- **H-34-015** — Relationship change history references episode/event/cause.
- **H-34-016** — Mystery stores level/core question/writer truth/audience beliefs/characters/clues/red herrings/false answer/partial answer/final payoff/open/resolution/status.
- **H-34-017** — Question stores priority/opened/last progress/parent mystery/answer/answer episode/status.
- **H-34-018** — Question statuses include Open/Partial/Paid/Reframed/Retired.
- **H-34-019** — Clue stores description/type/mystery/first appearance/visibility/initial interpretation/true meaning/audience memory/reactivation/payoff/status.
- **H-34-020** — Clue visibility includes Obvious/Noticeable/Hidden-in-plain-sight/Subtle.
- **H-34-021** — Invisible clue does not count as fair setup.
- **H-34-022** — Red herring may extend clue with true fact/wrong interpretation/secondary payoff.
- **H-34-023** — Prop stores name/visual/importance/holder/location/condition/story meaning/mysteries/last seen/history.
- **H-34-024** — Location stores visual/layout/entrances/features/lighting/story functions/events/continuity.
- **H-34-025** — Event is causal unit distinct from Scene.
- **H-34-026** — Event stores story time/location/participants/cause/effect/knowledge/relationship/prop/physical/audience changes.
- **H-34-027** — Arc stores question/objective/obstacle/audience theory/entry state/clues/twists/escalation/answer/reversal/exit/next question/status.
- **H-34-028** — Episode stores number/arc/title/duration/function/primary question/objective/obstacle/hook/clues/reward/reversal/state change/cliff/next question/production risk/status.
- **H-34-029** — Episode consumes input state and produces output state.
- **H-34-030** — Scene stores location/time/characters/purpose/wants/conflict/info before-after/props/relationship/emotion/entry/exit/risk/status.
- **H-34-031** — Shot stores scene/order/type/camera/refs/start/end/prop/screen direction/continuity anchor/visual purpose/asset/status.
- **H-34-032** — State stores scope/story time/character/relationship/prop/location/open questions/audience/version.
- **H-34-033** — Knowledge item references fact + state + source.
- **H-34-034** — Belief is distinct from knowledge.
- **H-34-035** — Audience State stores known facts/top theories/trust/active questions/expectation/emotion/boredom/confusion/writer trust.
- **H-34-036** — Theory stores support/confidence/viewer type/status/destroyed/resurrected.
- **H-34-037** — Twist stores belief before/truth/plants/reveal/consequence/new question/rewatch/score/status.
- **H-34-038** — Payoff stores setup refs/type/planned episode/answer/meaning/consequence/emotion/closure/status.
- **H-34-039** — Setup stores description/type/appearance/promise/payoff/status.
- **H-34-040** — Decision stores date/decision/status/reason/alternatives/affected/lock.
- **H-34-041** — Issue stores severity/category/location/problem/cause/evidence/fix options/recommended/affected/status.
- **H-34-042** — Mutation schema stores target/problem/preserve/mutable/axis/options/selected/ripple/score/status.
- **H-34-043** — Context Pack schema stores task/project version/role/entities/exclusions/canon/current state/constraints/instruction/status.
- **H-34-044** — Production asset stores type/entity/version/file/approval/supersedes/scope/notes.
- **H-34-045** — Normalize source storage then denormalize Context Packs.
- **H-34-046** — Broken reference flag: BROKEN_REFERENCE.
- **H-34-047** — Orphan flag: ORPHAN_ENTITY.
- **H-34-048** — Broken setup/payoff flags: BROKEN_PAYOFF_CHAIN / UNPAID_SETUP.
- **H-34-049** — Knowledge transition flag: KNOWLEDGE_TRANSITION_ERROR.
- **H-34-050** — Relationship jump flag: RELATIONSHIP_JUMP.
- **H-34-051** — Prop gap flag: PROP_TRANSFER_GAP.
- **H-34-052** — Causal time flag: CAUSAL_TIME_ERROR.
- **H-34-053** — Use enums for stable types/status, prose for nuance.
- **H-34-054** — Define required/recommended/optional fields.
- **H-34-055** — Use minimal schemas for early/minor entities.
- **H-34-056** — Validation strictness increases with Story OS state.
- **H-34-057** — Version schemas/migrations/backward compatibility/deprecation.
- **H-34-058** — Maintain schemas/CHANGELOG.md.
- **H-34-059** — project.yaml is top-level project manifest.
- **H-34-060** — sdcs.yaml can register modules/schemas/presets/commands.
- **H-34-061** — Preset inheritance: preset→project→arc→episode→scene.
- **H-34-062** — Hard constraint cannot be overridden by lower scope.
- **H-34-063** — Use data/ for normalized source and docs/ for human views when appropriate.
- **H-34-064** — Files may be MANUAL / GENERATED / SYNCED.
- **H-34-065** — Derived data never overrides source.
- **H-34-066** — Stable internal IDs are independent of display names.
- **H-34-067** — Entity tags can include core/spoiler/production_critical/high_risk/audience_visible/writer_only.
- **H-34-068** — Visibility levels: Public / Released / Character Only / Writer Only / Production Only.
- **H-34-069** — Visibility can be temporal by episode.
- **H-34-070** — State changes should reference source Events.
- **H-34-071** — Intentional coincidence/rule-break can be tagged and monitored.
- **H-34-072** — Validators may auto-create Issue entities.
- **H-34-073** — Structured Story QA/query becomes possible.
- **H-34-074** — Schema-valid does not mean story-good.
- **H-34-075** — Extensible fields/extensions allow genre-specific data.
- **H-34-076** — Metrics can be structured separately with history/version.
- **H-34-077** — Branch/project-version fields enable stale detection.
- **H-34-078** — Context retrieval can traverse graph Depth0/Depth1/Depth2 by task profile.
- **H-34-079** — YAML recommended for human-edited structured data.
- **H-34-080** — JSON Schema recommended for validation definitions.
- **H-34-081** — Markdown recommended for modules/screenplays/rationale/reports.
- **H-34-082** — Screenplay can remain Markdown/plain with stable scene IDs.
- **H-34-083** — Dialogue line IDs are optional.
- **H-34-084** — MVP schemas may begin Project/Character/Relationship/Mystery/Clue/Arc/Episode/State/Decision/Issue.
- **H-34-085** — Complexity profiles LIGHT / STANDARD / FULL.
- **H-34-086** — Ban arbitrary IDs.
- **H-34-087** — Ban unlinked duplication.
- **H-34-088** — Ban over-enum nuance.
- **H-34-089** — Ban early production requirements in early design.
- **H-34-090** — Ban silent broken refs.
- **H-34-091** — Ban overwrite history.
- **H-34-092** — Ban branch mixing.
- **H-34-093** — Ban newer draft overriding locked canon.
- **H-34-094** — Ban treating schema-valid as story quality.
- **H-34-095** — Ban over-complex schemas that create bureaucracy.
- **H-34-096** — Structure data only when it prevents error, improves retrieval or enables automation.
- **H-34-097** — Always distinguish Truth/Belief/Claim/State/Plan/Decision.

# v1.1 — CURIOSITY ARCHITECTURE

**Frozen design history.** Runtime consolidation does not delete these rules.

**Current operational owner:** `modules/01-curiosity-core.md`

## Frozen rules
- **H-11-001** — Design 30–50 episode series as layered curiosity architecture, not isolated hooks.
- **H-11-002** — Five broad arc functions may be Hook / Wrong Truth / Reversal / Hidden Game / Truth, adapted to project.
- **H-11-003** — Use Mystery Ladder so each answer deepens or reframes core question.
- **H-11-004** — Reveal types: Information / Identity / Motive / Meaning.
- **H-11-005** — Rotate reveal types to avoid repetitive progress.
- **H-11-006** — Micro reveal each episode is a useful default.
- **H-11-007** — Meaningful reward every 2–4 episodes is a useful default.
- **H-11-008** — Medium reversal every 5–8 episodes is a useful default.
- **H-11-009** — Major structural turn around one-third is a guideline.
- **H-11-010** — Story-changing turn around two-thirds is a guideline.
- **H-11-011** — Finale resolves core truth and final reframe.
- **H-11-012** — Curiosity Pulse: tension→reveal→brief relief→new problem.
- **H-11-013** — Arc engine: Question→Theory→Evidence→Answer→Reversal.
- **H-11-014** — Theory A may be surface-correct.
- **H-11-015** — Theory B should be reasonable but wrong.
- **H-11-016** — Theory C should be unexpected but supported.
- **H-11-017** — Use Suspicion Rotation rather than one static suspect.
- **H-11-018** — Track Trust Ladder.
- **H-11-019** — Track Curiosity Debt across arcs.
- **H-11-020** — Midpoint Bomb changes protagonist objective, not just adds information.
- **H-11-021** — 75% Crash destroys apparent solution and forces new strategy/cost.
- **H-11-022** — Final Truth should answer WHO / WHY / HOW / WHY NOW / WHY PROTAGONIST when applicable.
- **H-11-023** — Final Reframe should improve Episode 1 retrospectively.
- **H-11-024** — Audience should always feel closer to something.
- **H-11-025** — Every opened door should reveal another meaningful room.

# Mystery, Clue & Information Architecture
**Origin:** v1.6

- Give enough evidence to theorize, not enough for premature certainty.
- Clue must move truth, theory or twist preparation.
- Types: Direct / Behavior / Dialogue / Visual / Absence / Contradiction / Object / Timeline / Location / Sound.
- Ideal clue has two lives: initial interpretation and later true meaning.
- Hierarchy: Micro / Arc / Core. Core clues often appear before importance is known.
- Visibility: Obvious / Noticeable / Hidden-in-plain-sight / Subtle. Invisible does not count as fair setup.
- Fair-play: rewatch should reveal that solution was supported.
- Use echo/pair/triangle/collision to reactivate clue with changed meaning.
- Red herring = true fact + wrong conclusion + preferably secondary payoff.
- Carriers: object state, sound, costume, location, habit, memory.
- False memory should usually be true memory with wrong context/identity/time/meaning.
- Ledger statuses: Open / Partial / Paid. Track last progress and reactivation.
- Avoid clue-after-reveal, clue-without-function, rediscovery loops, late footprint dumping and clue contradiction with Writer Truth.
- Same data should support different interpretations until reveal.

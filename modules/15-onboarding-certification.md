# Orchestration, Onboarding, Certification & Packaging
**Origins:** v3.0, v4.2, v4.3, v4.4

## Orchestration
- Story OS is stateful. State + Gate + Bottleneck + Minimum Modules + Smallest Context + Validated Commit + Next Best Action.
- User override is respected through explicit unlock/update, never silent corruption.
- One Current Bottleneck; no shotgun repair.

## Onboarding
- Input types Raw Idea/Premise/Character/Twist/Scene/Genre/Image/Ending/Production/Existing Project.
- Detect CREATE/RESUME/IMPORT/CLONE/EXPERIMENT/PROTOTYPE.
- Extract explicit facts, constraints, Creative Spark and user priorities; provenance USER/IMPORTED/INFERRED/DEFAULT/PROPOSED/LOCKED_DECISION.
- Only ask high-information blocking questions; safe defaults are provisional.
- PROJECT_SEED contains working title, concept, protagonist, unusual situation, primary curiosity, stake, story lock, likely genre/format, assumptions, open decisions.
- Seed is not Blueprint. Initialize lean files lazily.
- Stop onboarding once next step can safely execute.

## Certification
- System certification and project certification are separate and evidence-based.
- Self-test levels: files/schema/modules/routing/behavior/E2E.
- No-Lost-Rule, source authority, branch isolation, audience firewall, portability and fresh-session recovery are release-critical.
- Project readiness: Concept/Blueprint/Writing/Production/Release Ready, each version-bound and invalidated by relevant change.
- Passing certification proves structural/process contract, not artistic masterpiece.

## Packaging
- Repo is product; SYSTEM is bootstrap; modules are runtime knowledge; history proves preservation.
- Historical v1.0→v4.4 remains; operational release = 1.0.0.
- Story Core feature-frozen. New core module requires capability gap + owner + tests + lineage + migration + certification.
- Model-specific image/video/voice orchestration belongs Production OS extension.
